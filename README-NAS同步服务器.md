# 观盘 Pro NAS 同步服务器

此目录提供可自行部署的 Docker Compose 服务。它兼容旧网页的 `/api/ping`、`/api/data`，并为原生 iOS 版提供独立的 `/api/native/ping`、`/api/native/data`。两个账本空间分开存储，不会相互转换或覆盖。原生同步包含账本、分时历史和日线缓存；服务器另保留最近 10 个账本快照。

## 部署

1. 先备份并停止旧容器，保留旧数据目录/卷；不要执行删除旧卷的清理操作。然后将 `nas-sync-server` 文件夹放到电脑或 NAS 上。
2. 在该文件夹执行 `docker compose up -d`。Compose 会拉取 Python 基础镜像并把服务器源码以只读方式挂载进容器，不需要先构建自定义镜像；支持 Compose 项目的 NAS 管理界面可直接导入 `compose.yaml` 启动。若你希望自行构建镜像，也保留了 `Dockerfile`。
3. 容器启动后会在日志中显示首次生成的同步口令。口令和 SQLite 数据库保存于 Docker 命名卷 `guanpan_pro_sync_data`；重建容器时保留该卷，不要勾选删除卷。
4. 在同一 Wi-Fi 下访问 `http://NAS局域网IP:8787/`，确认网页版能打开。网页保持原样随容器提供；未带口令的 `/api/ping` 会故意返回 `ok:false`，让网页继续直连行情源而不误走未配置的代理。旧网页的同步自查会携带口令访问该接口并得到 `ok:true`。
5. 原生 App 的“设置 → NAS 多设备同步”填写 `http://NAS局域网IP:8787` 和同步口令，点“测试连接”，之后开启自动同步。首次同步时，如果原生空间为空，会先迁入服务器上可识别的旧网页账本；没有旧网页数据时，本机空账本会下载原生账本，本机有数据且服务器原生空间为空则初始化上传；两边都有不同数据时会停下来让你选择。
6. 网页原有同步设置仍使用相同的地址和口令。网页数据保存于独立的旧网页空间，原生版不会覆盖它。若原生空间尚无数据，App 会把服务器上可识别的网页账本迁入原生空间并初始化同步；之后网页与原生仍按各自格式隔离同步，原生端后续修改不会自动反向转换回网页数据。

## 重要事项

- 容器使用 Docker 命名卷 `guanpan_pro_sync_data` 持久化数据库。重建容器时保留此卷。旧容器如果把数据存在其他文件名或卷中，新服务不会自动识别；换容器前先备份旧容器及其数据卷。旧网页设备上仍保留的数据可在新服务器启动后重新上传。
- 手动“从 NAS 下载”会覆盖本机原生账本；“上传到 NAS”会覆盖 NAS 原生账本。原生自动同步用版本比较，发现两端同时修改会暂停，不会静默强行覆盖。
- 自动生成的口令是高强度随机值。也可在 Compose 的 `SYNC_TOKEN` 中自行设定。更换口令后，所有网页和 App 设备都要同步更新。
- 默认服务使用 HTTP，适合仅在家中局域网访问。不要将 8787 端口直接暴露到公网；远程使用请通过 VPN 或配置 HTTPS 反向代理。
- 当前 API 单次请求最大 256 MiB。NAS 当前账本与历史缓存永久保留；仅服务器历史副本限制为最近 10 个版本。

## 数据隔离

| API | 用途 | 数据格式 |
| --- | --- | --- |
| `/api/data` | 现有网页同步 | 原网页 `_v:3` 完整数据包 |
| `/api/native/data` | 原生 App 同步 | 原生 `PortfolioData`、分时缓存、日线缓存 |

SQLite 数据库存储于 `guanpan_pro_sync_data` 卷的 `sync.sqlite3`。数据接口均要求同步口令；健康状态可通过打开根目录网页确认。
